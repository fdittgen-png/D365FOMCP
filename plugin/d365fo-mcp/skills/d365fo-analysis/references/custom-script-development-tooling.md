A set of PowerShell tools for creating, packaging, and managing D365FO Custom Scripts without Visual Studio.

| Script | Purpose |
|--------|---------|

| `Convert-ExcelToPODimensionXml.ps1` | Converts DMF error exports to XML input |
| `Diagnose-ExcelColumns.ps1` | Analyzes Excel column structure |

### 21.2 Convert-ExcelToPODimensionXml.ps1

**Purpose:** Converts Data Management error export files to XML format for `TBG_CS_PO_UpdateDimension` script.

**Version:** 3.2.0

**Key Features:**
- Auto-detects column positions from Excel header row
- Multi-pattern error filter with AND logic
- Company-specific dimension configuration
- Orphan lines handling with auto-generated headers

**Usage:**
```powershell
.\Convert-ExcelToPODimensionXml.ps1 `
    -HeadersExcelPath "GRUK_Purchase order headers V2_123.xlsx" `
    -LinesExcelPath "GRUK_Purchase order lines_456.xlsx"
```

### 21.3 Dimension Configuration per Company

**Config File Format:** `DimensionConfig_{Company}.json`

```json
{
    "DimensionOrder": ["BPC", "CostCenter", "Project", "Department", "Purpose", "Counterpart"]
}
```

**Dimension Order Examples by Company:**

| Company | Dimension Order (Position 1-6) |
|---------|-------------------------------|
| SPNO | BPC, CostCenter, Project, Department, Purpose, **Counterpart** |
| GRUK | BPC, CostCenter, Counterpart, Department, Purpose, ResourceGroup |

**Important:** The dimension order MUST match D365FO's `DimensionIntegrationConfiguration` for the company.

**Path in D365FO:** General Ledger > Chart of accounts > Dimensions > Financial dimension configuration for integrating applications

### 21.4 Error Filter Configuration

**Default Filters (AND logic - all must match):**
```powershell
-ErrorFilter @(
    "Results. You are attempting to enter values that will change the source document amounts for this purchase order",
    "Because invoicing of this purchase order has started, you are not allowed to make changes to these values"
)
```

**Why Multi-Pattern:** Error messages contain specific values (PO number, line number, quantity) that vary per record. Using multiple generic patterns filters correctly while ignoring specific values.

**Example Error Message:**
```
Results. You are attempting to enter values that will change the source document
amounts for this purchase order SPNO-PO-100322; line 63910400; quantity 40.00;
line number 3. Because invoicing of this purchase order has started, you are
not allowed to make changes to these values.
```

### 21.5 Orphan Lines Handling

**Problem:** Data Management validates headers and lines separately. A PO header might pass validation while its lines fail. This creates "orphan lines" - lines without matching header errors.

**Solution:** The script creates placeholder headers for orphan lines:

1. Lines without matching header are detected
2. Placeholder header created using **first line's dimension**
3. Header marked with `autoGenerated="true"` attribute

**Output XML:**
```xml
<PO id="PO-000002" dimension="BPC:ISP121" autoGenerated="true">
  <Line LnNum="3" dimension="BPC:ISP121-CostCenter:1050" />
  <Line LnNum="5" dimension="BPC:ISP121-CostCenter:1100" />
</PO>
```

**Processing Behavior:**

| Scenario | Header Action | Lines Action |
|----------|---------------|--------------|
| Header dimension matches current PO | No change (skipped) | Lines are updated |
| Header dimension differs from current PO | Header is updated | Lines are updated |

### 21.6 Column Auto-Detection

The script automatically detects column positions from Excel header row:

| Column Type | Detection Pattern |
|-------------|-------------------|
| Error | Contains "error" |
| Purchase Order | "Purchase order" or starts with "Purchase order" |
| Financial Dimensions | Contains "financial dimension" |
| Line Number | "Line number" or starts with "Line number" |

**Console Output:**
```
Auto-detected columns: Error=A, PO=D, Dimension=E, LineNum=F
```

### 21.7 Output XML Format

```xml
<?xml version="1.0" encoding="utf-8"?>
<PODimensionUpdate company="SPNO">
  <PO id="SPNO-PO-100264" dimension="BPC:ISP121-Counterpart:TPSNL">
    <Line LnNum="1" dimension="BPC:ISP121-CostCenter:1100-Counterpart:TPSNL" />
  </PO>
  <PO id="SPNO-PO-100322" dimension="BPC:ISP121" autoGenerated="true">
    <Line LnNum="3" dimension="BPC:ISP121-CostCenter:1100" />
  </PO>
</PODimensionUpdate>
```

### 21.8 Dimension Format

**Input (Excel):** `-ISP121-1100---TPSNL-` (dash-separated, position-based)

**Output (XML):** `BPC:ISP121-CostCenter:1100-Counterpart:TPSNL` (named format)

**Position Mapping:**
```
Position 1: BPC
Position 2: CostCenter
Position 3: Project (or varies by company)
Position 4: Department
Position 5: Purpose
Position 6: Counterpart (or ResourceGroup, varies by company)
```

### 21.9 File Naming Convention

**Excel Files (from Data Management):**
```
{Company}_{Entity}_{UniqueId}.xlsx

Examples:
- SPNO_Purchase order headers V2_639034168145291235.xlsx
- SPNO_Purchase order lines_639034168523148760.xlsx
```

**Company is auto-detected from filename.**
